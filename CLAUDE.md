# Automation Studio: project notes for Claude

Studio for X/Twitter and YouTube content about trading automation (ICT / Frank369). Films are canvas pages in `studio/films/<name>/` rendered by `studio/render.mjs` (Playwright frames piped to ffmpeg, BT.709, 60 fps for the masters). Audio is generated by `studio/audio*.py`. Masters go in `out/` (keep under 100 MB).

## Skills (installed in `.claude/skills/`)
- `frontend-design`, `canvas-design`, `algorithmic-art` from github.com/anthropics/skills.
- Remotion is NOT used in this project (no package.json, renders are canvas + ffmpeg), so the Remotion skills are not installed. If the project ever adopts Remotion, run `npx skills add remotion-dev/skills` and use `remotion-best-practices` from then on.

## Standing rules
- For every video or design change, apply `frontend-design` (distinctive, intentional aesthetic direction, typography, no templated defaults) and `algorithmic-art` (seeded, parameter-driven generative motion; every frame a pure function of t) before writing code. Use `canvas-design` for static posters and image cards.
- If `remotion-best-practices` is installed, follow it for any Remotion work as well.
- Trading content: all numbers simulated or sourced and labelled; keep the disclaimer "Not financial advice. For educational purposes only. Simulated data."; never invent Frank369 or ICT rules: ask the owner.
- Workflow the owner expects: render 3 still frames first (start, middle, climax), get approval, then the full render with audio, commit to `out/`, push.
